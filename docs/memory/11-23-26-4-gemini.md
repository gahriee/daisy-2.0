## Prompt 1: In-Memory Offline Navigation to Keep Sync Vault Unlocked Across Pages
**Timestamp:** 2026-11-23 23:45:37 (UTC+8)

### Prompt Goals
* Prevent offline page navigation from prompting for the sync password on every route change.
* Allow the Owner to unlock the offline copy once and navigate across all offline-capable pages while keeping the AES-256-GCM key strictly in memory (with the existing 15-minute inactivity auto-lock).

### Key Decisions & Rationale
* **Root Cause:** In offline mode, Next.js `<Link>` and `router.push` trigger RSC fetches (`RSC: 1`) that stay `network-only` in `src/offline/sw-policy.ts`. When those fetches fail offline, Next.js falls back to a hard full-document reload, which the Service Worker answers with the precached `/offline` shell—creating a fresh JS runtime and wiping the in-memory `VaultKeyCustody` key.
* **In-Memory Offline Navigation (`src/offline/navigation.ts`):** Added pure URL/click classification (`resolveOfflineClientNavigation`), `navigateOfflineInMemory` (`window.history.pushState` + scroll reset + `daisy:offline-navigate` event), `subscribeOfflineLocation` (`popstate` + custom event), and a capture-phase document click interceptor (`attachOfflineShellLinkInterceptor`) active only when `!navigator.onLine`. Setting `event.preventDefault()` without `stopPropagation()` makes Next.js `<Link>` bail out before fetching RSC while still letting React `onClick` handlers (such as closing the mobile sidebar drawer) run normally.
* **Race-Safe Route Dispatch & Live Shell State (`offline-route-fallback.tsx`, `workspace-shell.tsx`):** Mounted the capture-phase interceptor in `OfflineRouteFallback`, added a monotonic load sequence guard (`loadSeqRef`) plus pathname-matched `loadedRoute` state so rapid offline switches never display stale screens, and wired `useWorkspacePathname` in `WorkspaceShell` so sidebar highlights and breadcrumbs stay synchronized with client-side offline navigation.
* **Offline Form Post-Submit Redirects (`payment-create-form.tsx`, `maintenance-create-form.tsx`):** Routed offline post-submit navigation through `navigateOfflineInMemory` instead of `router.push` so queueing a payment or repair offline returns to the list view without reloading or locking the vault.
